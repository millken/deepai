# 会话上下文

长会话有两件不该发生的事：每一轮都把整段对话发给主模型，以及把大块工具输出嵌进提示词。这里的做法是把这两件事拆开。跨会话的用户记忆（`pkg/memory`）不承担这件事，仍然按原来的抽取和注入运行。

这不是先前那版「会话账本 + 把记忆改成默认关闭」。那一版在提示词末尾塞一份确定性的文件/失败摘要，并把持久记忆从热路径拿掉。当前实现不改记忆的开关，也不维护那份账本。

## 主模型看到的顺序

1. 系统提示（`ChatRequest.SystemPrompt`）。工具 schema 不写进这里。
2. 会话摘要。一条 `RoleHuman` 消息，标记 `session_summary`，不计入用户轮次。超过窗口的轮次由后台任务合并进这段文字。
3. 最近 N 个用户轮次的完整对话。默认 N = 10，含当前轮。一个用户轮次从一条真实用户消息算起，连同它后面的助手回复和工具结果，直到下一条用户消息。窗口打开时，这 N 轮不做 aging：工具结果和助手正文都不按年龄裁短。aging 只在窗口关闭（`session_keep_turns` 为负数，或 `AgentConfig.KeepFullTurns` 为 0）时作用于整段记录。
4. 当前轮的易变附注（日期、待办、任务章程、跨会话记忆）以及 `ChatRequest.Tools` 里的工具定义。

摘要必须是 `RoleHuman`。两条映射都会丢掉消息列表里的 `RoleSystem`，只有 `SystemPrompt` 会变成系统消息。

规范历史（`runMessages`、SQLite）不删。窗口只作用于发给模型的视图。`/history` 读的是全文。摘要任务读的是有界摘录，不是尾部切片：用户消息保留较长的开头（目标和约束所在）和较短的结尾，工具与助手消息保留较短的开头和较长的结尾（报错、退出码）。整段摘录不超过约 48KB。放不下时先去掉较早的工具输出，再去掉用户消息的结尾；用户消息的开头一起缩短，而不是把最早的轮次整段丢掉。

## 异步合并

用户轮次超过窗口时，`maybeStartSessionSummary` 在本轮开始时启动一次后台 `Chat`。它不走主模型的流式请求，也不占用本轮的截止时间：任务使用 `context.WithoutCancel` 加 60 秒超时。

- 一次只跑一个任务。`begin` / `complete` / `abort` 用递增的任务号。过期任务的 `complete` 不能覆盖更新的摘要。
- 任务读的是启动时已经渲染好的摘录，不读之后还会被改写的工具结果。后台任务如果 panic，会放弃这次飞行中的合并，下一轮可以重试。
- 摘要只覆盖已经掉出窗口的轮次。窗口内的原文留给主模型。
- 摘要还没写好时，提示词会写明哪些轮次正在合并、当前请求里没有它们。
- 进程重启后内存里的摘要会丢。恢复出来的第一轮先开窗口并注明缺口，后台任务用已保存的历史重做摘要，下一轮就能用上。`/clear` 和 `/new` 会换掉 `SessionCarry`，摘要一起丢掉。

子代理不设窗口，短任务仍发送完整记录。

## 工具结果

超过阈值的工具结果写入 `~/.deepai/offload/<call-id>.txt`（或 `OffloadDir`）。消息里只留：

- 以 `[offloaded: full output (` 开头的头，以及保存路径
- `ref: <call-id>`
- 约 15 行或 800 字节的尾部，用来保住 bash 的 `exit_code` 和常见的报错结尾
- 让模型在需要全文时调用 `recall_output`

`recall_output` 只接受 offload 目录里的 id 或该目录内的绝对路径，拒绝 `..` 和目录外路径。召回的正文留在当轮提示词里：结果带 `offload_exempt`，并且不受 50KB 存储截断。下一轮只要这轮还在窗口内，正文仍原样在。

## 配置

| 键 | 含义 |
| --- | --- |
| `session_keep_turns` | 原样保留的用户轮次数。缺省或 `0` 为 10。负数关闭窗口，发送全文。 |
| `session_summary_disabled` | 关闭后台摘要。窗口仍会丢掉更早的轮次，并注明没有摘要。 |
| `session_summary_model` | 后台摘要使用的模型别名。空则用当前对话模型，但是另一次 `Chat`。 |
| `tool_offload_bytes` | 超过该字节数就外置工具结果。缺省或 `0` 为 24 KiB。负数关闭外置。 |

窗口打开时，主循环不再按 0.75 阈值做主动压缩，也不再为那次压缩同步抽取记忆。窗口本身已经把旧轮次挡在请求外面。提供商报上下文溢出时，`compactOnOverflow` 仍会压缩，但只接受能缩小「实际发给模型的视图」（摘要 + 窗口内原文）的结果。只缩小未发送的旧历史、却不改变这次请求的压缩会被丢掉，避免为了一次无效重试改写摘要任务还要读的原文。窗口本身过大时，溢出兜底仍可能把规范历史里靠后的消息压短。

`AgentConfig.KeepFullTurns` 的零值表示关闭窗口，因此现有的单测和子代理行为不变。REPL 在解析配置时把缺省值换成 10。
