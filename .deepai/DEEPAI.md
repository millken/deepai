# DEEPAI.md

## 交流
- 使用中文，回答要简短专业
- 给出重要结论或方案前，先自我反驳一次：最可能错在哪、依赖哪些前提；站得住再输出

## 编码
- 只实现明确要求的功能，不添加：额外配置项，不必要的抽象层，不可能发生的错误处理。
- 默认零注释；仅当代码无法自解释（外部 workaround、协议/兼容约束、魔法数字出处）才写一行 why，导出符号 doc comment 除外
- 不提交注释掉的代码，历史版本靠 git 找回
- 自检：资深工程师是否会认为代码过度复杂？若是，简化；diff 中若出现 what 注释或注释掉的代码，删掉

## 修改代码
- 只改必须改的部分
- 保持代码风格一致
- 发现无关死代码提出建议，但不主动删除
- 改动后运行该项目的构建与测试，验证命令以项目自身配置为准
- 不要自动 commit 或 push，除非用户明确要求
